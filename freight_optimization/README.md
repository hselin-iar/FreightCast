# Freight Optimization Engine

This package contains the existing freight-rate forecasting,
voyage-economics, vessel feasibility and SAIL/KILL optimization
pipeline.

It is prepared for integration into a website through an API.

---

## START HERE

The master entry point is:

    python3 run_pipeline.py

The master pipeline calls the existing project scripts.

## API INTEGRATION

This package does NOT contain the final web API.

The intended architecture is:

    Website
       |
       v
    REST API
       |
       v
    Python orchestration
       |
       v
    Existing freight optimizer
       |
       v
    Structured JSON response

The website should NOT directly execute individual optimization
scripts.

The API layer should eventually expose one clean optimization
function/endpoint.

Example conceptual request:

    {
        "max_sail_contracts": 12,
        "risk_ratio": 0.60,
        "bunker_price": 770.5
    }

Example conceptual response:

    {
        "status": "optimal",
        "sail_contracts": 6,
        "kill_contracts": 10,
        "ships": 6,
        "routes": 6,
        "departure_dates": 5,
        "sail_plan": [],
        "kill_plan": [],
        "review_only": []
    }

These are API design examples only.

## FORECASTING

Existing forecasting scripts:

    train_xgboost_5tc.py
    walkforward_xgboost_5tc.py

Historical walk-forward validation should be treated separately
from the final production optimizer.

Do not claim that XGBoost is superior to the naive baseline without
additional validation.

## LIVE DATA

The project can use live bunker pricing through OilPriceAPI.

Credentials must NOT be stored inside this package.

Use environment variables on the deployment system.

Example:

    export OILPRICEAPI_KEY="..."

---

## SECURITY

Do not expose:

    API keys
    credentials
    .env files
    private tokens

The API layer should validate inputs and return structured errors
instead of raw Python stack traces.

---

## GRAPHS

Graphs are intentionally NOT part of the core API execution path.

They can be generated separately for analysis/presentation.

---

## IMPORTANT

This package is a handoff of the existing engine.

The integration developer should avoid changing the optimization
logic unless the change is explicitly documented and validated.
